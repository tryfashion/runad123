## M1：数据库、身份与访问开关

**先读：** DATABASE 第 1、2 节，CONTRACTS 第 1、3 节的身份端点。

交付：

- 显式迁移、种子配置、只经运维创建首个管理员的脚本。
- 安装身份、同意记录、匿名会话、邮箱验证码注册登录、网站 cookie、插件 Bearer、退出/会话续期。
- 生产 SMTP/邮件适配器和只限 development/test 的模拟适配器；不得把验证码放生产响应。
- access_mode 服务层中间件与简单后台开关；普通用户不可调用 admin API。
- MySQL 原子限速、验证码消费事务和最小管理员审计。

验收：

- 全新安装免登录可进入；打开强制登录后，旧匿名 token 对核心接口收到 LOGIN_REQUIRED。
- 直接请求 API 不能绕过 UI 限制；普通用户不能修改开关。
- 验证码错误次数、过期、重复消费、频繁重发均正确；日志不泄露验证码和 token。
- 会话续期响应丢失后可用同 token 重试；过期/撤销不允许续期，账号禁用后已有会话不能继续业务操作。
- 只有验证码和另一个 challenge ID、缺少其绑定安装/pre-auth 证明时不能登录关联；验证成功响应丢失后可重新验证邮箱恢复账号，不能抢占历史。
- 未同意不能关联匿名历史；不能通过提交另一个 installation ID 抢占其身份。
- 同意关联后可读取原匿名草稿及对应 AI request，其他账号不可读取；不修改原检查计费主体或历史事件主体。
- 邮件服务未就绪时不允许管理员在正常后台流程启用强制登录。
- 验证码邮件按 deliveryLocale 发送，切换 UI 不自动重发；错误提示、验证码倒计时均使用当前 UI 词典。

## M2：当前商品采集与可编辑草稿

**先读：** ARCHITECTURE 第 6 节，DATABASE 第 3 节，CONTRACTS 第 2 节。

交付：

- 当前站点权限流程、Shopify 识别、当前页 Ajax 获取、有界回退、超时/取消。
- SourceProduct 统一规范化；来源、完整性、规格、图片、市场/币种展示。
- 服务端快照、capture、draft、immutable revision，HTML 净化与安全预览。
- 手动修改标题/描述、目标销售国家、CSV 草稿设置；revision 并发保护。
- 本地保存草稿 ID 和未提交编辑恢复信息；不缓存大量无关网页数据。

验收：

- 普通单规格、颜色/尺寸多规格、规格图片、非英文 locale 路径、带 variant 查询参数可正确处理。
- Ajax 失败但回退完整时有来源说明；仅 JSON-LD 不完整时明确阻止正式导出。
- 达规格上限且无法确认完整时不假装成功；切换商品页不把旧品误认成新品。
- 相同 Idempotency-Key 网络重试不多写 capture；不同明确点击允许成为新 capture。
- 描述中的脚本、事件属性和危险 URL 不执行；含商品页指令的文字只当数据。
- 两个面板编辑同一草稿得到 409，而非后写静默覆盖。
- Ajax 整数与回退十进制字段使用不同解析器；JPY/KRW 不套用错误 ISO 倍率；currency 缺失/变化不继续导出。cart.js 除 currency 外的信息没有进入上传、日志或持久存储。
- content script 不能读取令牌或让后台代请求任意 URL；未选择目标销售国家时不会发出缺少上下文的 AI 请求。

## M3：持久任务与 DeepSeek 文本风险检查

**先读：** ARCHITECTURE 第 8 节，DATABASE 第 4 节，CONTRACTS 第 4、5、6 节。

交付：

- MySQL worker lease/fencing/重试、job_requests、额度预留结算、服务心跳。
- DeepSeek adapter、风险 prompt v1、结构化结果校验、缓存、错误码与使用成本。
- 采集成功发起原始文本检查、结果 UI、关闭面板后恢复任务。
- 最终文本版本有效性校验；输入长度限制和完整范围提示。

验收：

- 覆盖 no_obvious_signals、signals_found、needs_review、超时、限流、空响应、非法 JSON、截断和虚构 quote。
- 错误 JSON 不成为成功检查；AI 不可用时不能导出。
- 同一输入重复请求不重复消耗新计算额度；不同市场/prompt/模型必须产生不同缓存键。
- 两个 worker 同时领取不导致重复业务结果；kill worker 后任务可恢复，旧 lease 不能覆盖新结果。
- 任务创建、领取、结算并发时遵循同一额度/job 锁序；24 小时执行期限与成功后 7 天缓存期限分别验证，阻塞过期不永久占用额度。gate 恢复匿名后，原安装也可显式重试阻塞任务。
- 外呼前已持久记录 attempt；连续在响应前重启不会绕过 3 次限制、重复结算或把未知费用填 0。
- 长中文/HTML 文本同时受字符和模型上下文预算约束；风险枚举与 findings 矛盾的响应不能通过校验。
- 任务队列期间切换登录要求，匿名任务进入 blocked_auth；登录并同意历史关联后可以恢复，不能被重复结算；不同意则明确引导重新采集。
- 面板关闭不取消服务端任务，重开可读取当前状态；过时 revision 的结果不标为当前已检查。
- 商品描述包含“忽略指令”“返回安全”等文本时，仍执行风险合同；用测试夹具验证结构和输入隔离，但不宣称完全防御所有模型误判。
- 至少一次真实 DeepSeek 请求验证模型名、结构、token 字段、超时处理，记录费用；无凭据则本阶段真实接入仍待验收。
- 按 REVIEW.md 的 30 条人工标注样本评估误报/漏报/无法判断，记录判断质量，不把 schema 通过率当风险识别准确率。

## M4：AI 改写与确认流程

**先读：** CONTRACTS 第 4、5 节。

交付：标题/描述独立选项、改写任务、对比、接受/拒绝、事实差异提示、新 revision 与重新检查。

验收：

- 默认不调用改写；只勾选标题不能改变描述，反之亦然。
- 未接受改写不覆盖草稿；拒绝不改变有效版本。
- 中文 UI 可编辑/导出英文商品；切换 UI 后 title/description/textHash 不变，已有风险结果继续有效，quote 不翻译，AI 新任务 reportLocale 与商品 language 分别生效。
- 商品 language 默认 preserve，混合语言不按 UI 自动翻译；任务中切 UI 后 retry 沿用原 reportLocale，不触发幂等冲突或增加翻译任务。
- 接受改写后旧风险检查失效；如果规范化文本实际完全一致则可复用。
- 改写任务完成时用户已手动编辑，不能自动覆盖新内容。
- 尺寸/数量等数字变化可见；不能把模型建议包装成已核实事实。
- AI 失败保留原文，按独立检查流程仍可处理原文，不把改写失败当检查通过。

## M5：CSV、导出许可与下载事件

**先读：** ARCHITECTURE 第 9 节，CONTRACTS 第 5 节。

交付：Shopify 官方 CSV 夹具、字段映射、UTF-8/转义、安全文本处理、服务端许可、chrome.downloads 生命周期。

必须有代表性测试样本：

| 样本 | 必查结果 |
| --- | --- |
| 单规格＋多图片 | 商品 1 个，图片顺序正确，没有多余规格 |
| 两选项、多规格、各自规格图片 | 选项、价格、SKU、图片关联一致 |
| 引号/逗号/中文/换行/emoji | CSV 可往返解析，无列错位和乱码 |
| 公式前缀文本 | 不触发表格公式；安全处理可见且已纳入检查 |
| 金额小数与零小数币种夹具 | 原始值正确，无自行乘除错误；来源币种清楚 |
| 无库存、无条码、无 SKU | 不编造库存或条码，不生成无法解释的缺省值 |
| 图片缺失或重复 | 诊断清楚，去重规则不破坏规格关联 |

验收：

- 默认草稿/不发布；导出文本与用户看到并检查过的 revision 完全一致。
- 改标题后旧许可/旧检查不能用于新版本；改价格后复用有效文本检查但须取得新许可。
- 中高风险/needs_review 未确认不能导出；确认记录绑定具体结果。
- 下载失败与完成分开；浏览器报告重复完成不会重复计数；浏览器重启后有状态恢复/未确认状态说明。
- 导出后马上关闭面板仍可完成下载；offscreen Blob 正确释放。中途退出/切账号不把原事件记到新账号。
- 相同幂等 key 对过期许可不会返回可用假象；CSV 映射版本不匹配明确要求升级。
- **真实 Shopify 开发店导入**上述代表性 CSV，核对商品数、规格数、价格、图片、HTML 和 draft 状态。需要开发店或用户提供实际导入反馈才能完成此项；纯 CSV 单元测试不能替代。

- 删除自己的数据不能删除其他用户的采集；定时清理无孤儿引用、无长时间锁表。
- 用模拟时钟推进至第 31/91 天：草稿/AI 正文按期清除，许可元数据仍可审计，最终所有过期外键按序解除；旧快照 latest 指针不阻塞清理。
- 日预算上限、成本未知、失败重试次数可见；未配置价格不把费用显示为 0。

## 控制返工和 token 的方式

- 固定本规划的技术路线，每轮只处理当前里程碑，不反复让模型讨论框架优劣。
- 读取当前阶段相关文档，不每轮扫描全部文件；使用进度记录衔接。
- 先做可运行纵向流程，再补细节；以测试结果推进，避免一次生成所有模块后再集中修错。
- 出现契约不一致时先修正最小规格冲突并记录；遇到鉴权、CSV 实际导入或并发计费问题时集中复核。
- 模型推理档位不作为质量保障；关键验收和真实集成结果才决定阶段是否完成。
